# OML Multi-Route Admission and Controlled Evolution Design

Date: 2026-08-30
Status: approved direction, implementation pending design review

## 1. Purpose

This design upgrades Oh-My-LibRPA (OML) from the single admitted periodic 3D GW
route in release 0.3.1 to a versioned, evidence-driven harness for these workflow
families:

1. periodic 3D ABACUS + PyATB + LibRPA GW;
2. strict-2D ABACUS + PyATB + LibRPA GW;
3. molecular Delta-Sternheimer RPA;
4. periodic-solid Delta-Sternheimer RPA.

The immediate goal is not to declare every route production-ready. It is to
rebuild the software stack from pinned current sources on Fisherd, test the
actual source and file contracts, run bounded route smokes, and record enough
evidence to decide which routes may be exposed by the MCP service.

The long-term goal remains automated GW and RPA campaigns over hundreds of
perovskites, two-dimensional materials, altermagnets, and transition-metal
oxides. For that use, OML must reject known-invalid inputs before submission,
prevent duplicate work, localize failures, and evolve registered numerical
parameters under explicit resource and scientific gates.

## 2. Non-Goals

This phase does not:

- infer production validity from scheduler completion or process exit code;
- treat a small H2, Si, BN, or strict-2D smoke as a complete convergence study;
- automatically edit ABACUS, LibRPA, or PyATB source code;
- automatically promote a software profile, benchmark reference, or scientific
  threshold;
- overwrite an existing calculation or retry a failed stage in place;
- use the optional direct mixed-Fourier strict-2D Coulomb route as the default
  production method;
- admit magnetic, noncollinear, SOC, metallic, or DFT+U production campaigns
  solely because a nonmagnetic smoke passes.

## 3. Compatibility Generations

OML 0.3.1 keeps its existing compatibility profile and evidence unchanged. The
new stack is a separate compatibility generation, provisionally named
`abacus-librpa-2026-08-30-v2`.

| Component | Source channel | Pinned revision | Initial role |
| --- | --- | --- | --- |
| ABACUS | `AroundPeking/abacus-develop:master_ghj` | `641caa554b44c4db2743603e9c75c96379901d7c` | GW producer and Delta-Sternheimer response producer |
| LibRPA | `AroundPeking/LibRPA:master_ghj` | `7e40c5bbf735a78aa15fa589ca2468fec2e2427b` | GW/RPA consumer, strict-2D solver, and Sternheimer RPA solver |
| PyATB | `AroundPeking/pyatb:enable_head_wing` | `9fb9028c59b1dbaf9cf66965280961fc2225d9eb` | full-grid eigenvectors and head/wing velocity data |

The new LibRPA revision is not an ancestry-continuous update of the LibRPA
revision pinned by OML 0.3.1. Therefore:

- old 0.3.1 references remain valid only for their old profile;
- the old profile's strict-2D capability block remains unchanged;
- an old BN result may be used as a migration comparison, not an exact
  definition-matched regression reference for the new profile;
- no result crosses profile generations without an explicit comparison record;
- profile identifiers include exact revisions and build fingerprints, not only
  branch or release labels.

Every admitted build also records dependency revisions, compiler, MPI,
BLAS/LAPACK, ELPA, CMake options, executable SHA-256, host identity, and OML
schema/rule versions.

## 4. Intermediate Data Contract

Reader v1 is the production default for every route that supports it. Legacy is
available only through an explicit legacy compatibility profile or diagnostic
case. A plan must never discover and mix legacy and v1 payloads implicitly.

For v1 periodic GW routes, the producer contract includes:

- explicit ABACUS reader-v1 output selection;
- `stru_out` from the same producer run;
- `bz_sampling_out` as the authoritative Brillouin-zone sampling description;
- consistent wave-function, auxiliary-basis, shrink, Coulomb, and coefficient
  payload families required by the selected route;
- LibRPA v1 Coulomb and LRI reader selection;
- PyATB output generated by the pinned `enable_head_wing` revision.

Legacy symmetry sidecars are not copied. Spatial symmetry information is read
from `stru_out`, and LibRPA reconstructs the required rotations. OML must reject
a periodic symmetry dataset when `stru_out` is missing, belongs to another
producer run, or disagrees with `bz_sampling_out` and PyATB state dimensions.

PyATB output and symmetry behavior have changed. File names alone are not the
contract. Admission must create fixtures from the pinned revision and verify:

- format/version markers;
- full-grid and irreducible-grid counts;
- spin, k-point, band, eigenvector, and velocity dimensions;
- finite values and required Hermiticity relations;
- symmetry expansion/mapping consistency;
- compatibility with the pinned LibRPA reader.

The accepted fixture manifest, parser version, and payload checksums become
part of the compatibility profile.

## 5. Capability and Admission Model

Each profile declares route capabilities independently:

```text
BLOCKED -> TESTABLE -> EXPERIMENTAL -> ENABLED
```

- `BLOCKED`: the route cannot be materialized or executed.
- `TESTABLE`: only registered admission tests may execute; this is the initial
  state for a newly registered v2 route and is not evidence that tests passed.
- `EXPERIMENTAL`: bounded user-approved calculations may execute, but the route
  cannot supply production references.
- `ENABLED`: the route passed required convergence/physics gates and an explicit
  repository review promoted it.

Admission evidence is divided into non-substitutable levels:

| Level | Meaning | Minimum evidence |
| --- | --- | --- |
| L0 | source and build identity | clean pinned source, dependency/build receipt, executable hash |
| L1 | component behavior | selected ABACUS and LibRPA unit/regression tests pass |
| L2 | cross-program contract | reader-v1, `stru_out`, symmetry, PyATB, and LibRPA fixture round trips pass |
| L3 | bounded route smoke | complete registered stage graph, finite outputs, route-specific numerical gates |
| L4 | scientific acceptance | definition-matched regression and declared convergence axes pass |

L0-L2 alone permit no state higher than `TESTABLE`. Passing the route-specific
L3 suite permits a reviewed move to `EXPERIMENTAL`. L4 plus human review is
required for `ENABLED`. A score cannot compensate for a failed or missing
mandatory level.

## 6. Route Graphs and Gates

### 6.1 Periodic 3D GW

```text
reference_scf
  -> pyatb_full_grid
  -> nscf_band_path
  -> librpa_preprocess
  -> librpa_gw
  -> scientific_finalize
```

Admission uses the existing small BN reader-v1 dataset as a migration replay.
It verifies parser and route compatibility under the new profile but does not
claim exact regression continuity with OML 0.3.1.

Required L3 evidence includes:

- producer convergence and complete reader-v1 payloads;
- `stru_out`-based symmetry reconstruction without copied sidecars;
- PyATB full-grid/eigenvector/velocity consistency;
- complete LibRPA KS, EXX, and GW band tables with finite values;
- explicit QPE and analytic-continuation status;
- a recorded but not necessarily passing L4 state for `nfreq`, empty states,
  screening k-grid, and later basis-family convergence.

### 6.2 Strict-2D GW

```text
reference_scf_2d
  -> pyatb_full_grid_2d
  -> nscf_band_path_2d
  -> librpa_preprocess_2d
  -> librpa_gw_2d
  -> scientific_finalize_2d
```

The production candidate is the full strict-2D Ewald route with analytic Gamma
head/wing treatment. The direct mixed-Fourier positive-Gram route remains a
separately named opt-in diagnostic capability until it receives its own
admission and convergence evidence.

Required L1/L2 tests cover the current ABACUS strict-2D Coulomb/Ewald tests and
the current LibRPA head/wing and complete-`Wc` tests. Required L3 evidence
includes:

- explicit strict-2D geometry, in-plane area, vacuum, and q/k-grid metadata;
- full-Ewald Coulomb route identity and finite auxiliary Coulomb spectra;
- finite-q behavior plus analytic Gamma head/wing application;
- complete `Wc`, KS, EXX, and GW outputs with no missing symmetry channels;
- in-plane symmetry and full-grid mappings reconstructed from current payloads;
- a replay of an existing accepted producer dataset before any full new WS2 or
  other expensive producer calculation.

A strict-2D smoke does not establish vacuum, in-plane k-grid, frequency,
empty-state, auxiliary-basis, or final GW convergence.

### 6.3 Molecular Delta-Sternheimer RPA

```text
reference_ground_state_molecule
  -> sternheimer_response_molecule
  -> librpa_rpa_sternheimer
  -> scientific_finalize_rpa
```

The response stage is explicit. It must not be represented as an ordinary SCF
completion. Initial L3 admission uses H2 because it is lower cost than H2O.

Required evidence includes:

- the actual real-space grid and its relation to the declared plane-wave
  cutoff convention;
- FD8 Delta-Sternheimer route identity and operator/preconditioner settings;
- occupied-orbital and auxiliary-basis identities;
- frequency-grid metadata and per-frequency convergence markers;
- response residuals, iteration counts, finite output matrices, and complete
  frequency coverage;
- LibRPA Sternheimer reader acceptance and finite trace-log/RPA results;
- box-size, frequency-grid, grid-cutoff, PCA/auxiliary-basis, and molecular
  fragment requirements recorded as L4 convergence axes, not inferred from the
  smoke.

### 6.4 Periodic-Solid Delta-Sternheimer RPA

```text
reference_ground_state_solid
  -> sternheimer_response_solid
  -> librpa_rpa_sternheimer
  -> scientific_finalize_rpa
```

Initial L3 admission uses a small insulating Si case and a bounded representative
q/frequency subset. The subset is an admission test only; it cannot be reported
as a complete RPA energy.

Required evidence includes:

- folded response-target k-point and source-state mappings;
- actual real-space grid, FD8 route identity, and frequency metadata;
- analytic head/wing policy where required by the q-point;
- per-q/per-frequency convergence and residual completeness;
- finite Sternheimer response and LibRPA trace-log contributions;
- explicit ownership of all q/frequency channels so that a partial run cannot
  appear complete;
- grid, frequency, PCA/auxiliary basis, Coulomb metric, and k/q sampling listed
  as separate L4 convergence axes.

## 7. Source-Level Admission Suite

The pinned source trees are authoritative for test names and supported options.
The first Fisherd suite selects the relevant current tests, including:

- ABACUS strict-2D Coulomb head, Ewald Gaussian cutoff, MPI distribution, Ewald
  tail utilities, and Gaussian ABFS 2D integrals;
- ABACUS molecular and periodic Sternheimer operator, FD8, response, frequency,
  preconditioner, and output tests present at the pinned revision;
- LibRPA RPA head/wing tests, including strict-2D and complete-`Wc` behavior;
- LibRPA Sternheimer RPA reader/trace-log and q-summation tests;
- the bundled BN Sternheimer head/wing v1 regression where its fixture contract
  matches the pinned source.

The executable list and exact test filters are generated only after configuring
the clean pinned trees. Missing or renamed tests are reported as source-contract
changes and are not silently skipped.

## 8. Fisherd Execution Boundary

Fisherd is used for source admission and small route smokes. OML creates clean,
dedicated source, build, fixture, and run directories. It does not reuse the
older dirty ABACUS, LibRPA, or PyATB checkouts already present on the host as
evidence for this profile.

Resource limits for this phase are:

- at most 16 concurrent compile jobs;
- at most 48 CPU cores or software threads for any execution;
- bounded wall time and disk budget for every test group and route smoke;
- no full expensive WS2 producer calculation in the first strict-2D pass;
- no automatic migration to another host when a test fails.

Each local or scheduled execution obtains a content-addressed run identity and
an exclusive lock. Before launch, OML checks for equivalent live jobs/processes
and completed receipts. Existing outputs are retained; an altered parameter or
retry creates a fresh run directory.

## 9. Evidence and Receipts

Every build, test group, stage attempt, and scientific evaluation writes an
immutable machine-readable receipt. A minimum receipt contains:

```json
{
  "receipt_schema": "oml.receipt.v2",
  "campaign_id": "...",
  "case_id": "...",
  "route_id": "...",
  "profile_id": "abacus-librpa-2026-08-30-v2",
  "source_revisions": {},
  "build_fingerprints": {},
  "host_fingerprint": {},
  "input_manifest_sha256": "...",
  "plan_digest": "...",
  "stage": "...",
  "attempt_id": "...",
  "started_at": "...",
  "finished_at": "...",
  "resources": {},
  "process_status": "...",
  "artifact_manifest": [],
  "gate_results": [],
  "scientific_status": "NOT_EVALUATED",
  "promotion_eligibility": "BLOCKED"
}
```

Gate results record the validator version, measured value, threshold, status,
and evidence artifact. Scheduler or process completion is one observation, not
a numerical or scientific verdict.

## 10. Benchmark and Scorecard

The benchmark harness has hard gates and diagnostic scores. Hard gates are
non-compensating: a route with a failed stack, contract, finite-output,
completeness, or scientific gate cannot pass because other scores are high.

After hard-gate evaluation, the scorecard reports:

| Dimension | Weight | Examples |
| --- | ---: | --- |
| reproducibility | 20 | exact revisions, build/input hashes, immutable lineage |
| prevention | 15 | invalid-input rejection, duplicate prevention, stale-plan block |
| stage evidence | 20 | parser-backed artifacts, shape/finite/completeness checks |
| numerical evaluation | 15 | residuals, conservation/Hermiticity, stable finite outputs |
| scientific evaluation | 20 | definition matching and declared convergence axes |
| diagnosis quality | 10 | correct failure category and cheapest discriminating test |

Missing required evidence is `NOT_EVALUATED`, not zero and not pass. The harness
also tracks route-classification precision, failure-localization accuracy,
false-pass rate, false-block rate, duplicate submissions prevented, resource
cost, wall time, and context/tool-call cost.

Frozen fixtures include clean, incomplete, non-finite, mismatched-symmetry,
mixed-reader, stale-profile, and partial-q/frequency cases. Fault injection must
prove that known bad cases remain blocked as rules evolve.

## 11. Controlled Evolution

An evolution campaign consists of one reviewed baseline plus immutable candidate
runs. The controller may mutate only parameters registered for that route and
profile. One candidate changes one declared axis.

Initial registered axes are:

- periodic 3D GW: frequency count, empty-state count, screening k-grid, then
  separately NAO/ABFS/shrink settings;
- strict-2D Ewald GW: frequency count, empty-state count, in-plane k-grid,
  vacuum, and approved Ewald precision controls;
- molecular Delta-Sternheimer: box size, frequency grid, real-space grid/cutoff,
  PCA/auxiliary basis, and occupied-orbital basis;
- solid Delta-Sternheimer: real-space grid/cutoff, frequency grid,
  PCA/auxiliary basis, Coulomb metric, and k/q sampling.

The direct mixed-Fourier strict-2D route is excluded from automatic evolution
until separately admitted. If admitted later, its early controls are auxiliary
product-grid cutoff, out-of-plane reciprocal extent, and Gamma handling before
mesh and vacuum convergence.

Evolution rules are:

1. keep all non-axis definition fields fixed;
2. reject an equivalent existing or live candidate;
3. enforce campaign limits for candidate count, CPU time, wall time, and disk;
4. stop on stack/contract failure, repeated non-finite output, or loss of a
   previously passing hard gate;
5. retain every failed candidate and diagnosis receipt;
6. rank only candidates whose mandatory gates pass;
7. propose, but never perform, profile/reference/threshold promotion;
8. require human approval before expensive production scaling.

Source edits, new physical approximations, threshold relaxation, and route
changes are outside automatic evolution. They require a new experimental
profile, explicit tests, and repository review.

## 12. Failure Handling

OML classifies a failure at the narrowest supported boundary:

- source/build incompatibility;
- component test regression;
- reader or file-contract mismatch;
- symmetry/full-grid mismatch;
- producer nonconvergence or incomplete response channels;
- PyATB payload failure;
- LibRPA reader, Coulomb, head/wing, trace-log, or QPE failure;
- numerical instability or non-finite output;
- incomplete convergence evidence;
- unsupported scientific regime.

The diagnosis record cites observed evidence and proposes the cheapest
single-variable discriminating test. It does not submit that test automatically
unless the campaign policy explicitly allows the parameter and the current
budget, duplicate, and human-approval gates pass.

## 13. Implementation Order

1. Add the v2 profile schema, per-route capabilities, and admission-level model
   without changing the 0.3.1 profile.
2. Add receipt schemas, route-specific stage graphs, and stable blocked behavior.
3. Add source/build/test admission manifests and Fisherd execution profiles.
4. Build the pinned sources in clean Fisherd directories and run L0/L1 tests.
5. Capture and validate reader-v1, `stru_out`, symmetry, and PyATB/LibRPA L2
   fixtures.
6. Run bounded L3 smokes in this order: 3D BN migration replay, H2 molecular
   Delta-Sternheimer, Si representative-q solid Delta-Sternheimer, strict-2D
   existing-data replay.
7. Integrate only passing routes as `EXPERIMENTAL`; keep failed or missing routes
   blocked with stable reason codes.
8. Add controlled-evolution campaign objects, registered mutation axes, budgets,
   stop rules, and proposal-only promotion reports.
9. Run frozen replay/fault-injection benchmarks and publish the scorecard.
10. Plan separate L4 convergence campaigns before any route becomes `ENABLED`.

## 14. Acceptance Criteria for This Phase

This phase is complete only when:

- the old and new compatibility generations coexist without ambiguity;
- all new route plans default to reader v1 and never copy legacy symmetry
  sidecars;
- clean Fisherd builds and selected source tests have immutable receipts;
- current PyATB/symmetry payloads have parser-backed L2 fixtures;
- each attempted route has an L3 PASS, FAIL, or INCOMPLETE result backed by
  artifacts rather than a process-only status;
- no failed or untested route is enabled;
- duplicate prevention and fresh-run behavior are tested;
- controlled evolution cannot mutate unregistered parameters or promote policy;
- the benchmark scorecard preserves hard-gate failures and missing-evidence
  states;
- profile/reference promotion remains an explicit reviewed commit.
